## Not bugs (verified safe)

- **IDOR on the audited surfaces** — all new actions (`invoices.ts`, `travelers.ts`, `organizations.ts`, `admin-exceptions.ts`) enforce session + owner-org-member scope or `requirePermission`; `getBookingById` decrypts PII server-side only for authorized viewers. Middleware is fail-closed with permission-route mapping.
- **Payment idempotency & replay** — booking-scoped idempotency keys, 5-min webhook replay window, `WebhookEvent` unique constraint, per-booking single capture, HMAC-SHA256 with timing-safe compare (refactored into `src/lib/security/timing-safe.ts` by the current workstream).
- **Refund double-pay** — `Refund.idempotencyKey @unique` + REF-103 invariant (pending+refunded ≤ total) + deterministic admin key.
- **Oversell** — serializable holds, 100-concurrent test, lazy expiry of stale holds (`expiresAt > now` filter), 30-min stale-booking sweeper (in-process on Docker/k8s).
- **AI** — prompt-injection guard (EN+FA), output sanitization, MCP tool authorization, grounding service separating suggestions from bookable inventory; AI never mints bookings/prices.
