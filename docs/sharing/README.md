## چه چیزی اینجا آمده و چرا

سه فایل، **بدون تغییر** از ریپوی اصلی کپی شده‌اند. هر سه مستقل‌اند.

| فایل | چیست | چرا |
|---|---|---|
| `business-status-contracts.ts` | ۱۴۲ خط · **صفر import** | ماشین وضعیت هسته — قابل کپی در هر پروژه‌ای |
| `business-status-contracts.test.ts` | ۱۶۴ خط · **صفر import** | تست ماتریسی کامل — هر ۶۴ جفت وضعیت |

## چرا این را فرستادیم

دو ریپو به یک محصول اشاره می‌کنند: «تور فناوری فیروزو».

- **ریپوی همکار** (`firuzo-business`): هفت صفحه UI، ساخته و build می‌شود. صفر تست، صفر i18n، صفر بک‌اند.
- **ریپوی اصلی** (`itrip-platform`): مدل داده، ماشین وضعیت، دفترداری، i18n پنج‌زبانه، ۱۳۱۹ تست.

این‌ها **رقیب نیستند، مکمل‌اند.** بدون این فایل، همکار ماشین وضعیت را از صفر می‌سازد — و احتمالاً با ۸ وضعیت اما بدون تست ماتریسی و بدون خطای `invalid_transition`.

با داشتن این فایل‌ها: او ماشین وضعیت را برمی‌دارد، ما UI را درون معماری درست خودمان می‌سازیم، و **هیچ‌کدام کار تکراری نمی‌کند.**

## نکتهٔ مهم دربارهٔ تست

`business-status-contracts.test.ts` با `vitest` نوشته شده. ریپوی همکار vitest ندارد، پس برای اجرا:

```bash
npm i -D vitest
npx vitest run business-status-contracts.test.ts
```

خروجی مورد انتظار: **۶۴ تست پاس** (ماتریس کامل ۸×۸).

## کاری که از او نمی‌خواهیم

هیچ‌چیز را برنگردانیم. دلیلش در `docs/reference/README.md` آمده، ولی خلاصه‌اش:

- `app/*` او سگمنت `[locale]` ندارد و `next-intl` ندارد
- کامپوننت‌هایش الگوی خوبی دارند ولی باید درون سیستم i18n و Tailwind ما بازنویسی شوند
- کپی مستقیم، قرارداد مسیر و i18n این پروژه را می‌شکند

**الگو بگیر، کپی نکن.**
