# معماری هوش مصنوعی و پروتکل ابزارهای مسافرتی فیروزه (Firuzo / iTrip AI Architecture)

این سند معماری لایه هوش مصنوعی، روتر چندارائه‌دهنده، ابزارهای مبتنی بر استاندارد MCP و الزامات ضدتوهم (Anti-Hallucination) پلتفرم فیروزه را تشریح می‌کند.

---

## ۱. اصل بنیادین: ابزارمحوری در برابر چت‌بات‌های متوهم (Tool-Based vs. Fake Chatbots)

هوش مصنوعی در فیروزه هرگز مجاز نیست که رأساً اطلاعات پرواز، هتل، قیمت یا موجودی بلیت را اختراع (Hallucinate) کند. ساختار سیستم بر تفکیک قطعی دو لایه استوار است:

```
┌─────────────────────────────────────────────────────────────┐
│                       لایه استدلال کاربر                     │
│                 (کاربر: «۵ روز در استانبول»)                 │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│           روتر تشخیص نیت (Intent Router & Parser)           │
│     استخراج: مقصد: IST، روزها: ۵، مسافران: ۲، بودجه: متوسط  │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│          ابزارهای استاندارد MCP (Authoritative Tools)        │
│   ├── search_flights(origin, destination, date)             │
│   ├── search_hotels(city, checkIn, checkOut, stars)         │
│   ├── check_operating_hours(venueId, slot)                  │
│   └── estimate_transit_buffer(originCoords, destCoords)     │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│               پایگاه‌داده واقعی و تأمین‌کنندگان             │
│     (صندلی واقعی، قیمت رسمی، امضای HMAC موجودی معتبر)       │
└─────────────────────────────────────────────────────────────┘
```

## ۲. روتر تاب‌آور چندارائه‌دهنده (Multi-Provider Resilient Router)

سرویس `AiRouterService.ts` مجهز به پشتیبانی همزمان از چند ارائه‌دهنده تراز اول با اولویت‌بندی هوشمند است:

1. **اولویت اول:** Google Gemini (سریع و اقتصادی برای برنامه‌ریزی‌های چندمرحله‌ای)
2. **اولویت دوم (Fallback):** DeepSeek (پشتیبان قدرتمند استدلالی)
3. **اولویت سوم:** OpenAI GPT-4o
4. **اولویت چهارم:** Anthropic Claude 3.5 Sonnet

### فرآیند تاب‌آوری در برابر محدودیت نرخ (Rate-Limit Fallback):
- اگر ارائه‌دهنده اولیه خطای `HTTP 429: Too Many Requests` یا `Timeout` بازگرداند، درخواست بدون فوت وقت به ارائه‌دهنده دوم محول می‌شود.
- ارائه‌دهنده خطا دهنده به مدت ۱۰ دقیقه وارد دوره خنک‌سازی (Cooldown) شده و درخواست‌های بعدی مستقیم به ارائه‌دهنده فعال هدایت می‌شوند.

## ۳. استاندارد ابزارهای مسافرتی MCP (`travel-mcp-tools.ts`)

ابزارهای ثبت شده در پروتکل MCP فیروزه عبارتند از:
- `search_flights`: جست‌وجوی مستقیم صندلی‌های فعال در سامانه رزرواسیون فیروزه.
- `search_hotels`: استعلام هتل‌ها و ظرفیت اتاق‌های فعال با نرخ رسمی.
- `estimate_trip_budget`: محاسبه بودجه واقعی بر اساس هزینه‌های روزمره مقصد، نرخ ارز و تعداد نفرات.
- `check_schedule_conflict`: کنترل ساعات کار موزه‌ها و فضاهای گردشگری جهت جلوگیری از تداخل زمانی.
