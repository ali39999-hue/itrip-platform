# معیارهای قطعی تکمیل کار و پذیرش در فیروزه (Firuzo / iTrip Definition of Done)

این سند چک‌لیست رسمی پذیرش مهندسی (Definition of Done - DoD) در پلتفرم فیروزه است. هیچ تسک، کامپوننت یا قابلیتی تا زمان برآورده ساختن ۱۰۰٪ بندهای این سند به عنوان تکمیل‌شده علامت‌گذاری نخواهد شد.

---

## چک‌لیست جامع پذیرش نهایی (DoD Checklist)

### ۱. پیاده‌سازی و یکپارچگی کد (Code & Types)
- [x] کد تمیز، خوانا و منطبق با معماری لایه‌ای پروژه پیاده‌سازی شده است.
- [x] تایپ‌های تایپ‌اسکریپت به صورت صلب تعریف شده و از به کار بردن `any` اجتناب شده است.
- [x] دستور `npm run typecheck` با صفر خطا (Zero Errors) اجرا می‌شود.

### ۲. ارگونومی و ریسپانسیو موبایل (Mobile & Responsiveness)
- [x] کامپوننت در عرض‌های ۳۲۰، ۳۶۰، ۳۷۵، ۳۹۰ و ۴۱۲ پیکسل بدون اسکرول افقی ناخواسته تست شده است.
- [x] تمامی اکشن‌های اصلی (CTA) در ناحیه طبیعی شست (Sticky Bottom Bar) قرار دارند.
- [x] تمامی دیالوگ‌های انتخابی در موبایل به صورت Bottom Sheet کشویی پیاده شده‌اند.
- [x] مساحت تمامی المان‌های لمسی حداقل ۴۴×۴۴ پیکسل است.

### ۳. زبان و چیدمان راست‌چین (Persian RTL & Logical Properties)
- [x] هیچ کلاس جهتی چپ و راست سنتی (`left-`, `right-`, `ml-`, `mr-`, `pl-`, `pr-`) استفاده نشده و تماماً از کلاس‌های منطقی (`start-`, `end-`, `ms-`, `me-`, `ps-`, `pe-`) استفاده شده است.
- [x] تمامی متن‌های جدید در ۵ فایل زبانی (`messages/fa.json`, `en.json`, `ar.json`, `zh.json`, `ru.json`) تعریف شده‌اند.
- [x] آیکون‌های ناوبری جهت‌دار در زبان فارسی به درستی معکوس می‌شوند (`rtl:rotate-180`).

### ۴. وضعیت‌های رابط کاربری (UI States)
- [x] وضعیت بارگذاری (Loading Skeleton) استاندارد وجود دارد.
- [x] وضعیت بدون داده (Empty State) همراه با متن راهنما و دکمه اقدام وجود دارد.
- [x] وضعیت خطای سرور یا شبکه (Error State) با امکان تلاش مجدد (Retry) تعبیه شده است.

### ۵. دسترس‌پذیری و استانداردهای وب (Accessibility & WCAG AA)
- [x] تضاد رنگ متن و پس‌زمینه حداقل ۴.۵ به ۱ برای متن‌های عادی است.
- [x] نشانگرهای وضعیت صرفاً متکی به رنگ نبوده و دارای آیکون یا متن شفاف هستند.
- [x] قابلیت پیمایش کامل با کلید Tab کیبورد و هایلایت فوکوس فعال است.
- [x] تگ‌های معنایی `aria-expanded`، `aria-selected` و نقش‌های دیالوگ رعایت شده‌اند.

### ۶. پایداری و آزمون‌ها (Testing & Production Build)
- [x] تست‌های واحد مرتبط نوشته شده و در Vitest پاس می‌شوند.
- [x] کل مجموعه تست‌های پروژه (`npm run test:unit`) کاملاً سبز اجرا می‌شوند.
- [x] بیلد نهایی پروژه (`npm run build`) با موفقیت و بدون هشدار مسدودکننده کامل می‌شود.

### ۷. حقیقت محصول و راستی‌آزمایی (Product Truth Verification)
- [x] هیچ ادعای غیرواقعی بازاریابی بدون پشتوانه فنی در صفحه به کاربر نمایش داده نمی‌شود.
- [x] خروجی‌های هوش مصنوعی دارای برچسب تخمین و دیسکلیمر قانونی هستند.
- [x] تمامی تبادلات مالی از گاردریل لجر دوبل تراز صفر عبور می‌کنند.
