# معماری سامانه ERP و مدیریت آژانس فیروزه (Firuzo / iTrip ERP Architecture)

این سند مشخصات فنی، ماژول‌های عملیاتی، کنترل سطوح دسترسی (RBAC) و ابزارهای تجاری پلتفرم سازمانی فیروزه (Travel ERP 2.0) را تبیین می‌کند.

---

## ۱. ماژول‌های دامنه‌ای سیستم جامع سازمانی (ERP Modular Domains)

پنل ادمین فیروزه از یک داشبورد ساده فراتر رفته و به یک ERP تخصصی صنعت سفر با دامنه‌های تفکیک‌شده زیر ارتقا یافته است:

```
┌─────────────────────────────────────────────────────────────┐
│                    Travel ERP 2.0 Core                      │
├──────────────┬──────────────┬──────────────┬────────────────┤
│  عملیات سفر  │  مالی و تسویه│  مدیریت CRM  │  مدیریت سیستم  │
├──────────────┼──────────────┼──────────────┼────────────────┤
│ • رزروها     │ • لجر دوبل   │ • مشتریان    │ • کاربران      │
│ • تأمین‌کننده│ • کارتابل فیش│ • لیدرهای تور│ • نقش‌ها/مجوزها│
│ • مانیفست    │ • تسویه‌ها   │ • کد معرف    │ • لاگ ممیزی    │
│ • ظرفیت هلد  │ • مغایرت‌گیری│ • پروپوزال   │ • تنظیمات آژانس│
└──────────────┴──────────────┴──────────────┴────────────────┘
```

---

## ۲. صدور پروپوزال رسمی سفر (`TravelProposalService.ts`)

برای آژانس‌ها و سازمان‌ها، امکان تجمیع چند خدمت در یک پیش‌فاکتور رسمی با فرمت شرکتی الزامی است:
- تولید شناسه رسمی پیش‌فاکتور (مانند `PROP-2026-0042`).
- اعمال مارک‌آپ آژانس (Agency Markup) و محاسبه اتوماتیک مالیات ارزش افزوده (VAT).
- ارائه خلاصه پکیج شامل ردیف‌های پرواز، هتل، ترانسفر و گشت به همراه تاریخ سررسید اعتبار نرخ.

---

## ۳. ژنراتور مانیفست استاندارد مسافران (`PassengerManifestService.ts`)

ارائه مشخصات استاندارد مسافران به راهنمایان تور، ترانسفر و گیت پرواز:
- استخراج دیتای کامل: شماره ردیف، شماره سفارش، نام کامل مسافر، کدملی، شماره پاسپورت، تاریخ تولد، جنسیت، وضعیت سلامت و رژیم غذایی.
- خروجی پاکیزه با انکودینگ UTF-8 و BOM به منظور نمایش بدون مشکل فونت‌های فارسی در نرم‌افزار اکسل.

---

## ۴. جداسازی داده‌های چندمستأجره و کنترل دسترسی (Multi-Tenancy & RBAC)

- **ایزولاسیون آژانس‌ها:** هر آژانس همکار تنها به مسافران، سفارش‌ها و اسناد لجر مربوط به کد کاربری یا سازمان خود دسترسی دارد و تغییر پارامترهای URL منجر به پرتاب خطای دسترسی غیرمجاز (`403 Forbidden`) می‌شود.
- **ثبت لاگ ممیزی تغییرناپذیر (Immutable Audit Log):** تمامی عملیات پرخطر ادمین (تایید فیش بانکی، ابطال سفارش، واریز دستی وجه) همراه با شناسه کاربر، آدرس IP و مهر زمانی در جدول `AuditLog` ضبط می‌گردد.
