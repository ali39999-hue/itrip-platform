## آنچه عمداً نیاورده‌ایم و چرا

ریپوی همکار یک اپ Next.js مستقل است و **هفت صفحهٔ کارآمد** دارد، اما با معماری این پروژه نمی‌خواند. این‌ها را نیاوردیم:

| نیاوردیم | دلیل |
|---|---|
| کامپوننت‌های React | الگوی خوبی دارند، ولی باید درون سیستم طراحی و i18n این پروژه بازنویسی شوند |
| صفحات `app/*` | ساختار `app/` بدون سگمنت `[locale]` است و با قرارداد مسیر `src/app/[locale]/business/**` نمی‌خواند |
| `package.json` | next-intl و Tailwind ندارد؛ ادغامش i18n پروژه را می‌شکند |

**دلیل کلی:** ادغام کد به‌صورت کپی، ساختار نادرست را وارد می‌کند. الگو گرفتن بله، کپی کردن نه.

## آنچه واقعاً از آن‌ها ارزش دارد

- **توکن‌های طراحی** — سیستم `--fz-*` کامل و سازگار با سند. سشن frontend باید از همین استفاده کند.
- **دادهٔ دمو** — نوشتن سه پکیج با برنامهٔ روزبه‌روز و مسیر واقعی زمان می‌برد. این را به‌عنوان fixture در تست‌ها به کار ببرید.
- **تصمیم پول** — آن‌ها هم مستقل به «ریال صحیح، تومان فقط در نمایش» رسیده بودند (`formatToman`). این با تصمیم ما یکی است و تأییدش می‌کند.

## قوانینی که این پروژه دارد و ریپوی همکار ندارد

ریپوی همکار این‌ها را ندارد و ما آن‌ها را داریم — به همین دلیل کپی مستقیم جواب نمی‌دهد:

- `next-intl` با ۵ locale (`fa`/`en`/`ar`/`zh`/`ru`) — آن‌ها فقط فارسی هاردکد
- Tailwind با توکن‌های معنایی — آن‌ها CSS خام
- ۱۳۱۹ تست — آن‌ها صفر تست
- دیتابیس و API — آن‌ها فقط دمو در حافظه
- قاعدهٔ ESLint که دسترسی مستقیم به دادهٔ هسته را در عمودی بیزنس خطا می‌کند
