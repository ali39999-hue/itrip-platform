# UX Decision Log

Decisions here are binding for later implementation phases. Changing one requires a new entry, not a silent rewrite.

---

## D-001 — No product code in Phase 0 / Phase 1

**Date:** 2026-09-21  
**Decision:** Phase 0 (baseline) and Phase 1 (experience architecture) produce documents only.  
**Why:** The master prompt forbids redesign before inventory. Other sessions are active on `main` and worktrees. Touching `src/` now would collide and produce isolated patches.  
**Preserved:** All current routes, components, and business logic.

---

## D-002 — Isolated documentation root

**Date:** 2026-09-21  
**Decision:** All transformation docs live in `docs/ux-transformation/`.  
**Why:** `docs/baseline/` is being regenerated by another session. `docs/firuzo-route-audit.md` is historical and overly optimistic (many routes scored 8.5–9/10).  
**Do not:** overwrite `FEATURE_REALITY_MATRIX.md`, quality reports, or the old route audit.

## D-003 — Preserve working infrastructure

**Date:** 2026-09-21  
**Decision:** Do not throw away:

- Semantic tokens in `src/app/globals.css` (brand / brand-dark / action / ink / surface)
- `Button` variants `brand` and `action`
- Mobile primitives in `src/components/mobile/` (`FilterSheet`, `DatePickerSheet`, `StickyCTA`, …)
- Unified cart (`UnifiedCartService`, `UnifiedCartDrawer`, `/cart`)
- Checkout domain (`CheckoutApplicationService`, server-authoritative pricing)
- Trip artifacts (`BoardingPassCard`, offline voucher, countdown)
- next-intl 5 locales, logical CSS direction, `viewportFit: cover`
- Quality gates (`gate:a11y`, `gate:uiux`, typecheck, lint, unit)

**Why:** The prompt says complete the system, do not replace it.

## D-004 — Primary IA is five destinations, not a service catalog

**Date:** 2026-09-21  
**Decision:** Conceptual primary navigation:

1. HOME `/`
2. EXPLORE (today split across `/book`, `/destinations`, `/services`, `/tours`)
3. TRIPS `/my-trips`
4. WALLET `/wallet`
5. ACCOUNT `/account`

Flights, hotels, tours, plan, eSIM, insurance, visa, transfer, trains, city pass, CIP, interpreter are **secondary / contextual**, reached from Explore, Home search, or a Trip.

**Why:** Desktop `NAV_CATEGORIES.services` currently lists 11 equal items including flights and hotels *again*. Mobile bottom nav already has five slots; the mismatch is the label and target of slot 2 (`/book` labeled Search, not Explore).

## D-006 — Checkout remains one journey under Trip/Order context

**Date:** 2026-09-21  
**Decision:** Target checkout phases:

`Trip → Passengers → Services → Review → Payment → Confirmation`

Current stepper is `passengers → payment → issuing → success`. Addons exist inside checkout but are not a first-class phase. Do not create separate flight/hotel/tour checkout forms.

**Preserve:** `createBookingDraft` / `createMultiItemBookingDraftAction`, reprice, soft-lock timer, wallet pay, eCardo, card-to-card review.

---

## D-007 — Ancillary services attach to a trip

**Date:** 2026-09-21  
**Decision:** eSIM, insurance, transfer, visa, CIP, city pass, interpreter must offer **attach to trip** after purchase (or during checkout addons). Siloed product pages may remain as entry points.  
**Not in Phase 1 implementation.** Architecture only.

## D-008 — AI is not a sixth primary tab

**Date:** 2026-09-21  
**Decision:** `/plan` stays a secondary/planner surface. AI also appears as assist inside Search, Trip detail, and Support. It must never silently mutate booking or money. Pattern: SHOW → REVIEW → CONFIRM → APPLY.

## D-009 — Density modes, not one card skin

**Date:** 2026-09-21  
**Decision:** Six visual modes share tokens but not density:

| Mode | Used on |
|---|---|
| Discovery | Home, destinations, travelogues, tours browse |
| Search | Flight/hotel/tour results, map |
| Commerce | Detail CTAs, cart, checkout |
| Trip | My Trips, boarding pass, timeline |
| Finance | Wallet, invoices, payment methods |
| Admin | ERP tables (out of traveler IA) |

Do not force `AccountSidebar` onto Trip detail if it makes Trip feel like Account.

## D-010 — Reality matrix is authoritative for “is it live?”

**Date:** 2026-09-21  
**Decision:** UX must not imply live GDS/PSP where `docs/baseline/FEATURE_REALITY_MATRIX.md` says MOCK / DISABLED / COMING_SOON. Use `CapabilityBadge` and honest empty/error copy.  
**Examples:** flights inventory MOCK/BETA, hotels MOCK, Shetab DISABLED, Visa/MC and USDT COMING_SOON.

---

## D-011 — Definition of done is a flow, not a screenshot

A change is done only when: UX intent documented, UI hierarchy matches, responsive + RTL/LTR + a11y, loading/empty/error exist, business logic integrated, tests pass, new tests exist if the flow is critical, docs match code. Passing `gate:uiux` alone is not done.

## D-013 — One autocomplete; map is a hotels capability, not flights

**Date:** 2026-09-21 (Phase 4)  
**Decision:**
1. `CityAutocomplete` is the single city picker. `FlightSearchHeader`'s duplicate hand-rolled dropdowns were removed; header, SearchWidget forms, and the edit sheet all render the same component. Any future picker change happens in one file.
2. Map/list view is a **hotels** capability (already shipped: desktop side-by-side + mobile fullscreen). Flights stay list-only — results are route/timeline based, a geo-map adds no decision value and would fake parity. Do not add a flight map without a real use case.

**Why:** P1-004 (interaction model gap) and P1-005 (overlay sprawl) — the systemic fix is consolidation onto shared primitives, not more page-local chrome.
